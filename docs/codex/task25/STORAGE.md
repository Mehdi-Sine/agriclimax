# Stockage Task25

Choix : agrégats publics compacts, versionnés dans `apps/web/data/agriculture/`, lus côté serveur. Les parcelles, GeoPackages, archives et index d'identités restent dans `work/task25/` (ignoré par Git), jamais dans Postgres ou Supabase Storage. Un index généré d’imports serveur statiques assure le tracing Next/Vercel, indépendamment du répertoire de lancement du runtime. Aucun fichier agricole n’est importé par un composant client. Aucune clé Supabase n'est utilisée par la nouvelle API agricole.

SAA : 7 080 120 octets d'archive officielle ; environ 12,12Mo de fichiers JSON de restitution (mesure exacte dans `saa-import.json`). Les séries sont partitionnées par indicateur/maille ; une requête ne renvoie pas toute la base. Le RPG ajoute des agrégats pour les 713 PRA et des métadonnées de lots seulement. Ensemble agricole publié : **14 392 469 octets**, 520 fichiers JSON (`storage-measures.json`) ; ajout PostgreSQL nul. Les empreintes/statuts restent séparés des valeurs.

Ajout de stockage PostgreSQL/Supabase Storage : **0 octet écrit par cette Task**. Aucun changement de schéma, migration, RLS/grant ou droit `spatial_ref_sys`. Le volume global DB avant/après n'est pas mesuré : la connexion disponible est l'API REST, pas une session SQL d'administration. Il serait incorrect d'inventer une mesure de table/index. Les données climatiques DEV restent lues par le serveur existant.

Le plan d'acquisition officiel (`national-acquisition-plan.json`) mesure **10 945 220 073 octets** pour les 13 archives RPG. Leur conservation simultanée dépasse le disque du worker (7,9Gio). Le pipeline conserve donc intégralement et sans perte **la couche originale RPG_Parcelles.gpkg utilisée**, en XZ ; les couches Ilots/SNA/ZDH inutilisées ne sont pas conservées. Chaque cache comporte SHA256 original/compressé, taille, chemin de restauration, provenance de l'archive complète et vérification des octets décompressés.

Après un checkpoint complet et les contrôles d'empreintes, seules l'archive complète et sa copie de travail Parcelles sont évincées comme représentations redondantes de la source utilisée. Aucun effacement récursif ni autre fichier supprimé. Le contrôle automatique avait refusé l'ancienne suppression de répertoire ; la méthode plus étroite, avec rétention sans perte et vérification préalable, a été acceptée. Des tests vérifient la restauration exacte et la protection des fichiers non concernés, des empreintes divergentes et des liens symboliques.

Exemples mesurés : R11 72 732 672 octets originaux → 27 239 348 octets XZ ; R24 337 084 416 → 146 352 488 ; R27 475 508 736 → 208 855 704 ; R94 44 765 184 → 18 664 516. Le traitement régional et le cache compact permettent de poursuivre nationalement sans stockage payant. La taille nationale finale sera mesurée après les 13 lots ; la vérification de marge précède chaque extraction.

Budget annuel : environ 10,95Go de transferts pour une édition de taille comparable à 2025, conservation compacte des seules couches utilisées, plus quelques dizaines de Mo d'agrégats. Aucun coût monétaire inventé ni facturation engagée. Le workflow périodique ne vérifie que les catalogues ; aucun téléchargement massif automatique.
